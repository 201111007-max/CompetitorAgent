## 0. 设计依据：为什么报告正文质量需要一条防线

Lead 的 Final Answer 是**自由文本**，报告子系统（`assemble_comparison`）目前只做「剔 JSON + 拼正文 +
末尾追加提示/结论」，**不校验正文自身的结构质量**。本次会话实证：模型在单次 Final Answer 里同时写了
「草稿 + 正式稿」两份报告、把 aggregate 空结果消息抄进草稿、还在 JSON 处截断——管线原样落盘，产出
302 行的 `.md` 里**整份报告出现两遍**、中间夹着空提示与孤立标题、末尾是未闭合的代码块。

**核心认识**：报告正文是模型产物，质量缺陷只能靠**组装层的防御性净化**兜底，不能指望模型每轮都输出
结构完美的文本。

**已核实事实（不臆测，均读文件）**：`facade/comparison_report.py:90-110` 的 `assemble_comparison`
把 `lead_body`（`_lead_body_text` 剥离后的整段模型文本）原样拼接，末尾按**字符串存在性**判断是否追加
提示/结论（`_ZERO_CANDIDATE_HINT not in …`、`"## 市场格局核心结论" not in …`）；`_lead_body_text`
经 `react_report.py` 的 `_strip_json_blocks` + `_strip_structured_data_section` 净化。

## 1. 问题现状

### 1.1 整份报告在 `.md` 里重复两遍（最严重）

- **现象**：`output/compare.md`（302 行）中 `# Coding Agent 市场分析报告` 出现于**第 1 行与第 113 行**，
  `## 一、结论先行（TL;DR）` 出现 2 次；第一份（第 1-111 行）以「空 结构化数据 + 提示 + 孤立
  `## 市场格局核心结论`」收尾，第二份（第 113-302 行）是带完整聚合 JSON 的正式稿。
- **成因**：Lead 的 Final Answer 里**同时包含草稿与正式稿**；`assemble_comparison`（comparison_report.py:90）
  只做拼接不做去重。
- **影响**：读者看到同样的报告两遍；草稿里还夹着误导性空提示。**上轮的整节剥离只能删「七」段，
  删不掉一~六的重复**（实测剥离后 `## 一、结论先行` 仍为 2 次）。

### 1.2 报告尾部是截断的、未闭合的 JSON 围栏

- **现象**：compare.md 第 300 行 `"Quick Review agent` 处戛然而止，聚合 JSON 数组未闭合、无 ``` 收尾。
- **成因**：Lead 的最终回答在 JSON 处被截断（输出/配额限制），管线原样落盘。
- **影响**：`.md` 末尾一段是坏掉的代码块。注：当前 `_strip_structured_data_section` 对**末段**「七」会
  剥离到文末，已顺带清掉本次的截断尾；但若截断发生在其他章节（非「七」末段），仍会残留——需通用兜底。

### 1.3 模型把提示抄进正文、骗过代码的追加守卫

- **现象**：提示「未收集到候选数据（候选委派超时/失败），对比矩阵为空，置信度 0% 为事实。」出现在
  正文**中间**（compare.md 第 109 行），而非末尾。
- **成因**：本会话是**市场普查**（competitor="Coding Agent 市场…"），Lead 委派的是**维度子 Agent**
  （pricing/feature/performance/ecosystem/sentiment/roadmap）+ `aggregate_report`，**没有委派候选、
  也没有超时**——候选收集器为空是**设计使然**。Lead 把 aggregate 空结果消息抄进草稿的「七」段；
  代码本应在末尾追加提示/结论，却因守卫（comparison_report.py:99/104）看到「字符串已在正文」而**跳过**。
- **影响**：提示文案把「矩阵空」错误归因成「候选委派超时/失败」；且代码追加的提示/结论**丢失**。
- **已落地部分**：`_ZERO_CANDIDATE_HINT` 已中性化为「未收集到候选数据，对比矩阵为空。」（app.js:290 同步）；
  「模型抄写骗过守卫」的**机制问题未修**（待 §3.3）。

### 1.4 市场普查会话的 `compare.json` 是空壳、前端自相矛盾

- **现象**：`output/comparison/compare.json` 仅 234 字节：
  `{"schema_version":"1.0.0","competitors":[],"created_at":"2026-08-30T13:26:16Z","matrix":[],
  "best_per_dimension":{},"summary":{"competitors":[],"ranking":[],"coverage_gaps":{}}}`——尽管正文
  「七」段含 6 维聚合 JSON。
- **成因**：导出管线只读**候选收集器**（candidates）；市场普查走 `aggregate_report`（维度聚合），
  **不填 candidates**。
- **影响**：矩阵区显示「置信度 0% + 空矩阵」+「候选委派超时/失败」，与正文丰富内容自相矛盾；下载的
  JSON 无任何可用数据。属**产品设计缺口**：普查类报告被按「对比报告」渲染。

### 1.5 背景备注（非主线）：外部通道脆弱

搜索用量超限、Windsurf/OpenAI 官网反爬反复失败、SWE-bench/Terminal-Bench/Aider 榜单接口 404（→
performance 维度完全无数据、conf 0.2）、HN/Reddit SSL 失败。Lead 大量轮次花在重试自述上。**单一维度
无兜底通道**是独立工程问题，不并入本 doc 主线，仅记录。

## 2. 总体架构：组装层防御性净化

```
Lead Final Answer（自由文本，可能含草稿+正式稿 / 截断 / 抄写提示）
        │
        ▼
 组装层净化（新增，按 §3 逐项防御，全为纯文本变换，无 LLM 调用）
  ① 正文去重：H1 归并（§3.1）           —— 草稿+正式稿 → 只留正式稿
  ② 围栏兜底：未闭合 ``` 补闭合（§3.2）  —— 任意章节截断都收口
  ③ 追加守卫：字符串判断 → 布尔标志（§3.3）—— 模型抄写不再骗过守卫
        │
        ▼
  assemble_comparison 拼接 + 末尾追加提示/结论（comparison_report.py，改造后）
        │
        ▼
  .md 落盘 / compare.json 导出 / 前端矩阵
  ④ 普查模式导出决策（§3.4，产品层）     —— 普查 vs 对比是否同一渲染
```

**原则**：净化步骤全部是**确定性、无副作用**的文本变换——只在「异常形态」时触发（重复 H1、围栏失衡、
守卫被占），正常文本输出**逐字节不变**（黄金回归安全），与 doc 70 M1「正文在前、矩阵附录在后」的顺序
约定正交。

## 3. 接口设计

### 3.1 P1 报告正文去重（H1 归并）

```python
# react_report.py（在 _lead_body_text 内、_strip_structured_data_section 之后追加）
def _dedupe_repeated_report(text: str) -> str:
    """正文含 2+ 个 H1 标题（^# ）时，只保留最后一个 H1 起的内容（正式稿在草稿之后）。
    仅重复时触发；正常单 H1 文本原样返回。"""
    h1 = [m.start() for m in re.finditer(r"^#\s+[^\n]+", text, re.M)]
    return text[h1[-1]:] if len(h1) >= 2 else text
```

- **触发条件**：`^# ` 出现 ≥2 次（合法报告仅 1 个 H1，出现 ≥2 即草稿+正式稿）。
- **取尾**：保留最后一个 H1 起的内容（本次实证：正式稿与完整聚合 JSON 都在后半）。
- **附带收益**：copy1 尾部孤立的空「## 市场格局核心结论」随草稿整体消失。
- **风险**：若某报告刻意含两个一级标题（如正文 + 附录均用 H1），会丢正文前半——见 §6 权衡（可改为
  「重复 H1 后内容与前一 H1 内容高度重叠才归并」的增强判据，P1 先做简单版）。

### 3.2 P1 未闭合围栏兜底

```python
def _close_orphan_fence(text: str) -> str:
    """`` ``` `` 开/闭计数失衡（开 > 闭）时，在文末补一个闭合围栏；围栏已配平则原样返回。"""
    if text.count("```") % 2 != 0:
        return text.rstrip() + "\n```\n"
    return text
```

- 对**任意章节**的截断生效（不依赖「截断发生在七段」）；当前 `_strip_structured_data_section` 对末段
  「七」的整段剥离仍保留（两者互补）。

### 3.3 P2 追加守卫改布尔标志

```python
# comparison_report.py::assemble_comparison（comparison_report.py:96-110 改造）
appended_hint = False
if not comparison.markdown_report.strip():
    comparison.markdown_report = _ZERO_CANDIDATE_HINT + "\n"; appended_hint = True
elif not reports:
    comparison.markdown_report = comparison.markdown_report.rstrip() + "\n\n" + _ZERO_CANDIDATE_HINT + "\n"
    appended_hint = True
if conclusion and "## 市场格局核心结论" not in comparison.markdown_report:
    comparison.markdown_report = (... + "\n\n## 市场格局核心结论\n\n" + conclusion + "\n")
```

- **要点**：把「字符串是否已在正文」的存在性判断，改为**代码是否已追加**的布尔标志，杜绝模型抄写
  提示/标题文本后代码追加被跳过。
- **结论段**：保留「标题已在正文则不再追加」的防重复判断（避免模型已写结论时重复）；但配合 §3.1 去重
  后，模型正文里孤立的「## 市场格局核心结论」多数已被归并掉，二者协同。

### 3.4 P3 普查模式结构化导出决策（产品层，需确认）

| 方案 | 行为 | 代价 |
|---|---|---|
| **A（现状）** | 普查会话不产矩阵/compare.json；前端对普查类不显示矩阵，改为显示维度聚合摘要 + 中性提示 | 前端需按 `comparison.competitors 为空` 区分渲染；改动最小 |

## 8. 核心技术点总结

- **报告正文是模型产物，质量靠组装层防御性净化兜底**：去重（H1 归并）、围栏收口、守卫布尔化，三者
  全部确定性、仅对异常形态触发、正常文本逐字节不变。
- **提示/结论的追加判断从「字符串存在性」改为「代码布尔标志」**：杜绝模型抄写文本骗过守卫导致
  提示/结论丢失（本次实证：提示被抄进正文中间、代码版追加被跳过）。
- **市场普查（aggregate_report）会话不填候选收集器**：矩阵/compare.json 空壳是产品设计缺口，需
  「普查不产矩阵（推荐，方案 A）」或「聚合 → 矩阵映射（方案 B）」二选一，前端同步按 competitors 空区分渲染。
- **已落地（同轮）**：`_strip_structured_data_section` 整节剥离、提示文案中性化、置信度 chip 移除，
  web_app PID 37272 已上线；本文档记录**待实施**部分（P1 去重/围栏、P2 守卫、P3 普查决策）。
