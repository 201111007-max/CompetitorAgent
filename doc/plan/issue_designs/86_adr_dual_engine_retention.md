# 设计文档 86 —— 第三十六轮：ADR——为什么保留双引擎对照（react/langgraph 长期共存）

> 形态：**ADR**（工单 11 三篇精选之三）。与 doc 84 互补：84 答「为什么主引擎自研」，本文答「既然主引擎自研，为什么还花钱养一个 LangGraph 路径不删」。

| ADR 字段 | 内容 |
|----------|------|
| 状态 | 已采纳（doc 51 起维持；本 ADR 明确其存续条件与退出条件） |
| 关联文档 | doc 51（双引擎对照设计）、doc 78（并发压测不涉 langgraph）、doc 76（评测版本化将快照双引擎指标） |

## 1. 背景

`engine="react"/"langgraph"` 双路由已落地。删除 langgraph 路径可省维护成本；保留则需回答「它的存在理由是什么、什么时候删」。

## 2. 决策

**保留双引擎，但角色不对等：react 是主路径（功能演进只发生在这里），langgraph 是对照实验引擎（功能集冻结在对照所需最小面）。同时明确退出条件，避免永久双维护。**

## 3. 理由

1. **架构声明的可证伪性**：「自研编排比图编排更适合本项目」是一个主张。保留一个真实可跑的 LangGraph 实现（非稻草人 demo），让 benchmark 可随时复跑对照（llm_calls/cost/wall/accuracy），主张从「口头」变为「可证伪的实验结论」——这是评测驱动项目的自我要求。
2. **控变量设计的教学价值**：doc 51 的对照刻意「LLM/工具/记忆/事件/报告出口逐位一致，唯一变量是编排层」——这是面试中最硬的叙事之一：「我们不仅做了抽象对比，还把对比做成了可复跑的实验」。
3. **差异化结论是资产不是欠账**：取消/预算/checkpoint 不对齐（doc 51 §1.2）明确写为差异化结论——它证明了自研层承载的隐性复杂度（护栏与编排的耦合深度），反过来支撑 doc 84 的主决策。
4. **退出条件明确**（防无限双维护）：满足任一即删 langgraph 路径——① 连续 2 个版本周期对照结论无变化且无新编排问题需要实验；② LangGraph 升级导致适配成本超过其对照价值；③ 项目进入纯运营期无架构叙事需求。

## 4. 后果

- 正面：架构主张可证伪、可复跑；新编排优化（如 doc 81 停滞检测）可先在双引擎上对照再定去留。
- 负面：langgraph 路径的功能冻结意味着 Web/CLI 的部分新特性（如停滞检测注入）在 langgraph 路径不生效——对照实验的口径一致性优先。
- 缓解：退出条件写死；`engine` 参数对用户可见但文档标注「experimental/comparison only」。

## 5. 验证/证据

benchmark `--engine both` 对照报告（既有）；doc 76 版本化后每份快照携带 `engine` 维度指标，对照表随历史自动积累。
